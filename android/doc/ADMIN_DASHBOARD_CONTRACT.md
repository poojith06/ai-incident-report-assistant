# Admin dashboard contract (knowledge graph)

The future admin dashboard needs two things from the app and gives one thing back. All of it is plain JSON, with no network code in
the app today: the app only QUEUES documents; a future sync job delivers them.

| Direction | Document | Where in the app |
|---|---|---|
| app -> dashboard | `IncidentAnalysisExport` (one per analysed incident) | queued in `files/kg/outbox/<incidentId>.json` by `FileAnalysisOutbox` |
| app -> dashboard | audit log `RecommendationLog` (one per incident, reproducible) | `files/kg/audit/<incidentId>.json` by `FileAuditStore` |
| both ways | `GraphPack` (versioned graph: nodes, edges, sources, normalization rules) | `files/kg/packs/<version>.json`, pointer `files/kg/active.txt`; `AdminGraphService.exportPack` / `importPack` |

Code: `knowledgegraph/AnalysisExport.kt`, `knowledgegraph/model/*`, `knowledgegraph/admin/*`, `knowledgegraph/repository/*`.
Real examples (generated by `SampleOutputTest` from the seed pack): `doc/samples/kg/INC-2026-0001.analysis-export.json` and
`doc/samples/kg/INC-2026-0001.audit-log.json` (one pair per sample incident, 0001 to 0012).

## 1. `IncidentAnalysisExport` (schemaVersion 1)
One document per incident, created when the reporter submits (reporter audience, i.e. exactly what the reporter saw). Re-running the
analysis of an incident replaces its queued document. `schemaVersion` changes only for incompatible changes; consumers must ignore
unknown fields.


Field rules
- `incident` holds graph facts only. There is NO reporter, NO injured person, NO name. For residential location types (the pack's
  `normalization.residentialLocationTypes`, e.g. a hostel room) `locationLabel` is null and `locationRedacted` is true.
- `recommendations[].id` is always a `RECOMMENDATION` node of graph version `graphVersion`; `sourceId` is the SOP source it relies on;
  `provenance` lists the graph paths (edge ids in brackets) that produced it; `rank` is per phase (1 = first); `score` follows spec
  section 12 (weights in `EngineConfig`). `renderMode` is `TEMPLATE` (canonical text), `LLM` (validated re-phrasing) or `FALLBACK`
  (the LLM reply failed validation, canonical text shown). `unverifiedDraft` is false in reporter exports.
- `suppressed` lists every candidate removed and why (spec section 13): approval, expiry, safety, medical, authorization, prerequisite,
  phone number, duplicate, limits, missing facts.
- `unresolvedQuestions` has at most one entry. `abstained` true means nothing was suggested because facts were missing (the question says which).
- `responsibleTeams[].contactNumber` is set ONLY for a verified, enabled, unexpired contact; the seed has none.
- `medicalFooter` is the fixed footer text for injury cases.

## 2. Audit log `RecommendationLog` (spec section 8 `kg_recommendation_log`)
`files/kg/audit/<incidentId>.json`: `id`, `incidentId`, `graphVersion`, `audience`, `createdAt`, `userConfirmed`, `abstained`,
`recommendationIds`, `shown[]` (id, kind, phase, rank, score, sourceId, provenance, renderMode), `suppressed[]`, `unresolvedQuestions`,
`warnings`, `historyCitations`, `inputFacts` (type, severity, status, locationType, assets, hazards, peopleAffected, effects, injury,
evidenceConfidence). With the graph version and `inputFacts` a run can be reproduced.

## 3. `GraphPack` (schemaVersion 1) import/export
```json
{
  "schemaVersion": 1, "packVersion": 3, "name": "iiit-h-seed", "description": "", "createdAt": "2026-10-11T00:00:00+05:30",
  "nodes":   [ { "id": "action:isolate-asset", "type": "ACTION", "name": "...", "properties": { "phase": "OPERATIONAL", "userCanPerform": false, "requiresAuthorization": true, "canonicalText": "...", "canonicalKey": "ISOLATE_AFFECTED_ASSET", "orderClass": "HAZARD_ISOLATION" }, "verificationStatus": "NEEDS_ADMIN_VERIFICATION", "version": 1, "active": true } ],
  "edges":   [ { "id": "edge:...", "sourceId": "incident-type:computer-fire", "relation": "TRIGGERS_ACTION", "targetId": "action:isolate-asset", "conditions": { "statuses": ["ACTIVE","CONTAINED"] }, "priority": 91, "sourceRef": "sop:demo-seed:v1", "approvalStatus": "APPROVED", "version": 1, "active": true } ],
  "sources": [ { "id": "sop:demo-seed:v1", "title": "...", "version": "1", "uri": null, "approvedBy": "...", "approvedAt": "2026-10-11T00:00:00+05:30", "expiresAt": null, "status": "APPROVED", "displayLabel": "..." } ],
  "normalization": { "incidentTypes": [], "locationTypes": [], "assets": [], "hazards": [], "operationalEffects": [], "statuses": [], "buildings": [], "residentialLocationTypes": [] }
}
```
The tables map one to one to the spec's SQL tables (`kg_node`, `kg_edge`, `kg_source`) so a SQL migration is mechanical. Node and edge
property conventions, edge condition operators and the normalization rules: `doc/KNOWLEDGE_GRAPH.md` and `app/src/main/assets/kg/README.md`.
Templates for admins (CSV and a pack template): `app/src/main/assets/kg/templates/`.

Import rules (`GraphValidator`, enforced by `AdminGraphService.importPack` and by every admin edit): decode is strict (unknown keys
are errors); no duplicate ids or codes; no dangling edge ends, `sourceRef`s, recommendation `actionId`s or SUPPORTED_BY sources; no
prerequisite (`DEPENDS_ON`) cycle; every ACTION has a valid phase, text and the two authorization flags; the production approval rule
(an APPROVED recommendation needs a source, `approvedBy` and a readable `approvedAt`; an `expiresAt` must be an ISO date); no medical,
phone-number or unsafe-instruction text; no enabled contact without verification. A rejected import stores nothing. An accepted import is
installed as the NEXT version (its own `packVersion` is replaced) and activated; older versions stay, so rollback is just activating one.

## 4. Admin API surface (`AdminGraphService`)
| Method | What it does |
|---|---|
| `importPack(json): ImportResult` | validate, store as next version, activate. Throws `AdminException` (with the `ValidationReport`) when invalid. |
| `exportPack(version?): String` | JSON of a stored version (active by default). |
| `upsertNode(node)`, `upsertEdge(edge)` | apply a change on a copy of the active pack as a new version (validated, activated). |
| `disable(id)` | node or edge inactive; a recommendation also becomes DISABLED. |
| `attachSource(source, recommendationId?)` | add or replace an SOP source (with expiry) and optionally point a recommendation at it. |
| `approveRecommendation(recId, reviewer, expiresAt?)` | production rule: needs an existing APPROVED, unexpired source and a reviewer; sets `approvalStatus`, `approvedBy`, `approvedAt` (now). |
| `verifyLocation(nodeId, by)`, `verifyTeam(teamId, by)` | set `VERIFIED` with `verifiedBy` / `verifiedAt`. |
| `validate(): ValidationReport` | dangling references, prerequisite cycles, approval rule, text rules for the active pack. |
| `preview(incident, audience, history)` | what an incident would get from the active graph (`ADMIN_PREVIEW` shows draft and unverified guidance labelled `unverifiedDraft`); writes no audit log. |
| `rollback(version)` / `versions()` / `activeVersion()` | switch the active pointer. |

The app exposes `AppContainer.graphAdmin` for this; no screen uses it yet. A dashboard can drive the same operations over the same JSON.

## 5. Sync (future)
`AnalysisOutbox.pending()` lists incident ids with a queued export; `read(id)` gives the document; `acknowledge(id)` removes it after
delivery. A packs endpoint on the dashboard would deliver a new `GraphPack` JSON to `importPack`. The outbox and audit files hold no
identities, but they are local files of the app: a transport must be authenticated and encrypted.

## In-app dashboard (ADR-058)
The in-app admin dashboard (`doc/ADMIN_DASHBOARD.md`) consumes exactly these files: `files/kg/audit`, `files/kg/outbox`, the packs under `files/kg/packs` and the reports, so everything in this contract is visible on the device today. Its graph highlight is derived from the `provenance` strings of the audit log and the export (`incident-type:x -TRIGGERS_ACTION-> action:y [edge:id]`): those strings are therefore part of the contract (hops separated by ` -RELATION-> `, ids as in the pack). No field was added to the audit or the export for the dashboard.
